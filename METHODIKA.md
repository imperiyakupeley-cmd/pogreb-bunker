# Методичка: премиум-лендинги на статике (HTML/CSS/JS + GitHub + Cloudflare Pages)

**Компания:** Империя Купелей, Краснодар. Полипропилен: погреба, бункеры-укрытия, купели, бассейны. >3000 изделий, 8 лет.
**Стек (зафиксирован):** рукописная статика (1–N HTML-файлов, без фреймворков и сборщиков), GitHub, Cloudflare Pages, свой домен. 0 ₽/мес хостинг.
**Цель:** премиум-лендинги + органический трафик без платной рекламы. Поисковик №1 — Яндекс, аудитория РФ.
**Референс:** `index.html` в этом репозитории (погреба/бункеры, цены от 158 900 ₽, WhatsApp +7 993 320-55-65, тел. +7 861 213-22-15).

Три принципа всего методички:
1. **Один сайт = одна цель.** Каждая страница ведёт к одному действию (заявка в WhatsApp/звонок).
2. **Премиум = типографика + воздух + честность**, а не градиенты и анимации. Аккуратная статика выглядит дороже кривого WordPress-шаблона.
3. **Не врать ни пользователю, ни поисковику.** Уникальный текст, реальные цифры, реальные сроки. За генерацию пустых страниц Яндекс пессимизирует (фильтры «Баден-Баден», АГС).

## 0. Чек-лист запуска нового сайта: от нуля до индексации

Порядок обязателен. Каждый пункт — либо «сделано», либо сайт не запущен.

### Этап A. Домен и хранилище
- [ ] Купить домен у регистратора (.ru, ~200–900 ₽/год). Имя: продукт + регион или бренд (`pogreb-bunker.ru`). Короткое, без дефисов в середине слов, кириллицу не брать.
- [ ] Создать репозиторий на GitHub (private). Структура: корень = `index.html`, рядом `robots.txt`, `sitemap.xml`, `404.html`, `favicon.svg`, папка `img/`.
- [ ] Добавить домен в Cloudflare (аккаунт → Add domain), на регистраторе сменить NS-серверы на выданные Cloudflare. Ждать активации (обычно минуты—часы).

### Этап B. Cloudflare Pages
- [ ] Workers & Pages → Create → Pages → Connect to Git → выбрать репозиторий. Build command: пусто. Output dir: `/`. Production branch: `main`.
- [ ] Custom domains → добавить домен. SSL выдаётся автоматически, принудительный HTTPS включён по умолчанию.
- [ ] Положить в корень файл `_headers` (кэш-правила и безопасность, см. раздел 5.5).
- [ ] Проверить: `curl -sI https://домен/` → `HTTP/2 200`, и `curl -sI https://домен/несуществующая` → 404 (страница `404.html` на месте).

### Этап C. Обязательные файлы (до подачи в Яндекс)
- [ ] `index.html` — главная/лендинг по структуре раздела 1.
- [ ] `robots.txt` и `sitemap.xml` (шаблоны — раздел 3.7). В sitemap только канонические URL, `lastmod` — реальная дата изменения.
- [ ] `favicon.svg` (+ при желании `apple-touch-icon.png` 180×180).
- [ ] На каждой странице: `<html lang="ru">`, title, description, canonical, OG-теги, JSON-LD (раздел 3.6).
- [ ] Счётчик Яндекс.Метрики (раздел 0, этап D) — до подачи в индексацию, чтобы работал «обход по счётчикам».

### Этап D. Яндекс: панели и настройки
- [ ] **Вебмастер** (webmaster.yandex.ru): добавить сайт, подтвердить права (DNS TXT — удобнее всего для домена на Cloudflare).
- [ ] Главное зеркало: `https://домен` без www (Индексирование → Переезд сайта).
- [ ] Регион: Настройки → «Региональность» → Краснодар (для сайта компании; гео-страницы — раздел 4).
- [ ] Загрузить sitemap: Индексирование → Файлы Sitemap → указать `https://домен/sitemap.xml`.
- [ ] **Метрика**: создать счётчик, вставить сниппет перед `</body>`. В Вебмастере связать счётчик и включить «Обход по счётчикам» — страницы с реальным трафиком индексируются быстрее.
- [ ] **Яндекс Бизнес**: создать/заполнить карточку организации. Название, адрес, телефон — **до символа те же, что на сайте** (NAP-консистентность — сильный локальный сигнал; то же в 2ГИС).
- [ ] Файл-ключ IndexNow в корне (`<ключ>.txt`) — для мгновенного оповещения об изменениях (см. 7.4).

### Этап E. Первая индексация
- [ ] Вебмастер → Индексирование → «Переобход страниц» → отправить главную и 2–3 ключевые страницы (лимит квот, не лить весь сайт).
- [ ] Через 2–4 дня проверить: `site:домен` в Яндексе; в Вебмастере «Страницы в поиске».
- [ ] Не в индексе через 7–10 дней → проверить «Безопасность и нарушения», диагностику, потом повторить переобход.
- [ ] Проверить сниппеты в выдаче: title не обрезается, в description попала цена/УТП.

**Норма: первый трафик из органики — 2–8 недель после индексации.** Быстрее — только контентом и гео-страницами, не «трюками».

## 1. Структура страниц

### 1.1. Скелет конверсионного лендинга производителя

Порядок блоков (сверху вниз). Основа — модель «Hero → Боль/Решение → Доказательство → CTA»:

| # | Блок | Что внутри | Правило |
|---|------|-----------|---------|
| 1 | Шапка + Hero | Логотип/строка бренда, H1 с главным ключом и УТП, подзаголовок с конкретикой (материал, срок службы, монтаж), 1 главная кнопка (WhatsApp) + телефон, 3–4 чипа фактов («>3000 изделий за 8 лет», «от 158 900 ₽», «монтаж за 1 день») | H1 = оффер, а не «Добро пожаловать». CTA видим без скролла |
| 2 | Продукты | Карточки: фото, название, цена «от», 4–6 характеристик, мини-CTA | Цена обязательна: «по запросу» режет конверсию и вреден для Яндекса (коммерческий фактор) |
| 3 | Почему мы / материал | 4–6 карточек преимуществ с конкретикой (не «качество», а «стенки 10 мм, монолитная сварка») | Каждое преимущество — проверяемый факт |
| 4 | Как проходит заказ | 4–6 шагов с числами (сроки, что входит) | Снимает страх «а что дальше» |
| 5 | Доказательства | Производство: фото цеха, цифры, отзывы, кейсы монтажей | Без реальных фото блок не делать |
| 6 | FAQ | 5–8 вопросов `<details>` с честными ответами | Контент для FAQPage-разметки |
| 7 | Финальная форма | Форма расчёта + телефон + WhatsApp | Дублирует hero-CTA для дочитавших |
| 8 | Футер | Полные контакты, адрес производства, юр. данные, ссылки на статьи/гео-страницы, дисклеймеры | Контакты текстом (не только картинкой) — сигнал для Яндекса |

### 1.2. Правила блоков
- **Одно главное действие на страницу.** Один тип CTA (у нас — заявка в WhatsApp/звонок); повторять один и тот же CTA можно и нужно каждые 2–3 экрана.
- Каждые ~3 экрана — либо CTA, либо блок доверия. Не давать 5 экранов «о себе» подряд.
- CTA-текст — от выгоды: «Получить расчёт за час», не «Отправить».
- Телефон — кликабельный `tel:`, WhatsApp — `https://wa.me/79933205565?text=...` с предзаполненным текстом заявки (как в `index.html`).
- Никаких внешних скриптов-виджетов чатов: каждый виджет = минус к скорости и точка отказа.

### 1.3. Структура статьи (блог)
1. H1 — вопрос/задача пользователя («Как выбрать пластиковый погреб для дачи»).
2. Лид-абзац: ответ в 2–3 предложениях + для кого статья + кто автор (производитель, 8 лет).
3. Оглавление с якорями (3–7 пунктов).
4. Основная часть: H2 по шагам/аспектам, списки, таблицы сравнения, реальные фото.
5. Блок FAQ (2–4 вопроса) с FAQPage-разметкой.
6. Финальный CTA: «Рассчитать погреб под ваш участок» → продуктова страница/форма.
7. Обязательные ссылки: 1 на продуктовую страницу + 2–3 на смежные статьи (раздел 6.4).

### 1.4. Продуктовая страница (когда продуктов несколько)
`/pogreba-iz-polipropilena/`, `/bunkery/` и т.п. Скелет: Hero с ценой → таблица моделей (размер/комплектация/цена) → материал → монтаж → FAQ → форма. Product-разметка (3.6). Из главной — ссылки на каждую.

## 2. Дизайн-система «премиум без дизайнера»

Готовые цифры. Отклонения — только осознанно, дефолт — эти значения.

### 2.1. Палитра: 2 акцента + нейтрали
База прототипа (проверенная):

```css
:root{
  --bg:#f7f5f0;        /* фон страницы, тёплый светлый */
  --card:#ffffff;      /* карточки */
  --ink:#1e2a23;       /* основной текст, почти чёрный с оттенком */
  --muted:#5b6a61;     /* вторичный текст (проверен контраст на светлом фоне) */
  --green:#1f5c3d;     /* АКЦЕНТ 1: бренд, кнопки, цены */
  --green-d:#14402a;   /* тёмные секции */
  --sand:#d9c9a3;      /* АКЦЕНТ 2: песочный, детали/подложки */
  --accent:#c96f2e;    /* редкий акцент (ссылки-выделения), <5% площади */
  --line:#e3ddd2;      /* границы */
}
```

Правила:
- 60/30/10: нейтральный фон — 60%, тёмный бренд — 30%, акценты — 10%.
- Акцентных цветов ровно 2 (+1 редкий). Каждый новый цвет = дизайн дешевеет.
- Тёмные секции чередовать со светлыми — ритм страницы.
- Текст на тёмном зелёном — `#fff` или `#cfe0d3`-класса (контраст ≥ 4.5:1).

### 2.2. Типографика (шкала, rem)
- Базовый размер: `html{font-size:16px}`, body: `1.0625rem` (17px), реже 18px. Межстрочный: body 1.55–1.65, заголовки 1.1–1.2.
- Шрифты: системный стек (как в прототипе) — 0 КБ, 0 запросов, премиум-достаточно. Если нужен фирменный — один woff2, subset, `font-display:swap`.
- Шкала размеров (шаг ~1.25, «большая терция»):

| Токен | rem | px (base 16) | Применение |
|---|---|---|---|
| `fs-xs` | 0.8125 | 13 | подписи, дисклеймеры |
| `fs-s` | 0.875 | 14 | чипы, футер |
| `fs-m` | 1 | 16 | inputs, кнопки |
| `fs-body` | 1.0625 | 17 | основной текст |
| `fs-l` | 1.25 | 20 | H3, лид |
| `fs-xl` | 1.5 | 24 | H2 mobile |
| `fs-2xl` | 2 | 32 | H2 desktop |
| `fs-3xl` | clamp(1.75rem, 5vw, 2.75rem) | 28–44 | H1 |

- H1 и H2 — резиновые через `clamp()`: `h1{font-size:clamp(28px,5vw,44px)}` — читабельно от 360px до 1440px без media-queries.
- Заголовки ≥24px — чуть уплотнить: `letter-spacing:-0.5px`. КАПС-надписи (бренд в шапке) — наоборот расширить: `letter-spacing:.12em`.
- Максимальная длина строки текста: 65–75 символов (`max-width:70ch` или ~720px).

### 2.3. Сетка отступов (8pt)
Все отступы/размеры кратны 4 или 8:

```
4, 8, 12, 16, 24, 32, 48, 64, 96
```
- Вертикальный ритм секций: `section{padding:64px 0}`, mobile: 44–48px.
- Внутри карточек: 24–32px. Между карточками сетки: 16–24px. Между заголовком и текстом: 8–12px. Между блоками текста: 16–24px.
- Контейнер: `max-width:1080px; padding:0 20px` (на мобильном боковые поля ≥16px).
- Сетки: `repeat(auto-fit,minmax(240px,1fr))` — колонки сами схлопываются, без ручных breakpoint'ов.

### 2.4. Радиусы и тени
- Радиусы: элементы ввода — 10px; карточки/кнопки — 12–14px; чипы — 999px. Один набор на весь сайт.
- Тени — 2 уровня, мягкие, с цветом чернил, не чисто-чёрные:
  - карточка: `0 1px 3px rgba(30,42,35,.06)`
  - ховер/подъём: `0 8px 24px rgba(30,42,35,.12)`
- Границы вместо тяжёлых теней: `1px solid var(--line)` — так дешевле и аккуратнее.
- Ховер-состояния у всех кликабельных: смена фона/тени + `transition:.15s`. Фокус: `outline:2px solid var(--green)` (не убирать!).

### 2.5. Доступность (WCAG 2.1 AA) — обязательный минимум
- Контраст: текст ≥ **4.5:1**; крупный текст (≥24px или ≥19px жирный) и иконки/рамки ≥ **3:1**. Проверять пары WebAIM Contrast Checker (webaim.org/resources/contrastchecker).
- Вся информация — текстом, не только цветом (цена — не только зелёным, но и «от … ₽»).
- Изображения: `alt` у содержательных, `alt=""` у декоративных.
- Кликабельное ≥44×44px (пальцевая зона), `cursor:pointer`.
- Формы: `label for` у каждого поля (как в прототипе), фокус видим.
- Анимации — только `prefers-reduced-motion`-безопасные; без мигалок.

### 2.6. Антипаттерны «дешёвого» сайта
Никогда: тёмный фон всей страницы под текст; 4+ шрифта/начертаний; градиентные заголовки; автоплей видео/звука; счётчики иконок-«наград» без ссылок; параллакс; карусели (пользователи не листают — лучше статичная сетка).

## 3. SEO-чеклист постранично

### 3.1. Title — формулы (лимит видимости в Яндексе ~50–60 симв., обрезка по пикселям ~500–570px)
Ключ — в начало. Шаблоны:
- Главная: `{Продукт} из полипропилена от производителя в Краснодаре | {Бренд}`
- Продуктовая: `{Продукт}: цены от {X} ₽, монтаж за 1 день | {Бренд}`
- Гео: `{Продукт} в {Город} — доставка и монтаж | {Бренд}`
- Статья: `{Как/Что} {ключевая фраза} — гайд 2026 | {Бренд}` (для статей бренд можно убрать ради ключа)
Запрещено: перечисление ключей через запятую, КАПС, «!!!», одинаковый title на всех страницах.

### 3.2. Description (150–170 симв.; Яндекс показывает до ~170)
Формула: `оффер + конкретика (цена/срок/цифра) + CTA`.
Пример (проверен в прототипе): «Погреба и бункеры из пищевого полипропилена от производителя. Герметичность, срок службы 30+ лет, монтаж за 1 день. Погреб — от 158 900 ₽. Доставка по России из Краснодара.»
Если description не соответствует тексту страницы, Яндекс подставит свой кусок из контента — писать честно.

### 3.3. Заголовки
- **H1 ровно один**, = главный ключ страницы, ≠ word-в- word title (дополняйте: title короче и с брендом, H1 длиннее и конкретнее).
- H2 — по смысловым блокам (вопросы — лучший вариант: «Нужен ли бетон под погреб?»). H3 — внутри H2. Не прыгать H2→H4.
- Текст с ключами — естественный: вхождения в H1/H2/первом абзаце/alt; плотность не считать, переспам = риск «Баден-Бадена».

### 3.4. URL
- Нижний регистр, дефисы, кириллицу можно (`/pogreba/`, `/pogreb-krasnodar/`) — но для домена .ru удобнее латиница в путях.
- Без `.html` на конце (CF Pages отдаёт `/path/` → index.html), без параметров, без дат в URL статей.
- Каждая страница: `<link rel="canonical" href="https://домен/полный/путь">`.

### 3.5. Изображения
- `alt` с описанием по-человечески, у ключевых — с вхождением («Погреб из полипропилена 1,5×1,66 м на участке»).
- Обязательны `width` и `height` (или `aspect-ratio`) — иначе CLS.
- OG-теги для шаринга: `og:title`, `og:description`, `og:image` (1200×630), `og:type`.

### 3.6. Микроразметка JSON-LD — готовые шаблоны

**Organization (на всех страницах, в `<head>`):**
```html
<script type="application/ld+json">
{"@context":"https://schema.org","@type":"Organization",
 "name":"Империя Купелей",
 "url":"https://pogreb-bunker.ru/",
 "logo":"https://pogreb-bunker.ru/img/logo.png",
 "address":{"@type":"PostalAddress","addressLocality":"Краснодар","addressCountry":"RU"},
 "telephone":"+7 (861) 213-22-15",
 "sameAs":["https://t.me/...","https://vk.com/..."]}
</script>
```

**LocalBusiness (главная или /contacts/):**
```html
<script type="application/ld+json">
{"@context":"https://schema.org","@type":"LocalBusiness",
 "@id":"https://pogreb-bunker.ru/#business",

   "dayOfWeek":["Monday","Tuesday","Wednesday","Thursday","Friday","Saturday"],
   "opens":"09:00","closes":"20:00"}]}
</script>
```

**Product + Offer (продуктовая страница):**
```html
<script type="application/ld+json">
{"@context":"https://schema.org","@type":"Product",
 "name":"Погреб из полипропилена 1,5 × 1,66 × 1,83 м",
 "image":"https://pogreb-bunker.ru/img/pogreb-1500.jpg",

 "material":"Полипропилен",
 "offers":{"@type":"Offer","url":"https://pogreb-bunker.ru/pogreba/",
   "priceCurrency":"RUB","price":"158900",

```
`aggregateRating` ставить только при наличии реальных отзывов на сайте — выдуманные = нарушение.

**FAQPage (страница/блок FAQ; тексты 1-в-1 как на странице):**

### 3.7. robots.txt и sitemap.xml — шаблоны

`robots.txt` (в корне):
```
User-agent: *
Allow: /

Sitemap: https://pogreb-bunker.ru/sitemap.xml
```
Для маленького сайта этого достаточно. robots.txt управляет обходом, НЕ индексацией: не прятать там то, что должно быть в поиске. Служебные файлы (`_headers`, ключ IndexNow) поисковику не мешают — CF не отдаёт `_headers` наружу, а txt-ключ робот не индексирует как страницу.

`sitemap.xml` (все канонические страницы, `lastmod` формат `YYYY-MM-DD`):
```xml
<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
 <url><loc>https://pogreb-bunker.ru/</loc><lastmod>2026-09-27</lastmod><priority>1.0</priority></url>
 <url><loc>https://pogreb-bunker.ru/pogreba/</loc><lastmod>2026-09-27</lastmod><priority>0.9</priority></url>
 <url><loc>https://pogreb-bunker.ru/blog/pogreb-dlya-dachi/</loc><lastmod>2026-09-20</lastmod><priority>0.7</priority></url>
</urlset>
```
Лимиты: 1 файл ≤ 50 000 URL / 50 МБ (нашим сайтам далеко). Правило честности: `lastmod` обновлять при каждом реальном изменении страницы — иначе робот перестаёт доверять карте.

## 4. Гео-страницы «продукт + город»

Максимально опасный раздел: массовые страницы «то же самое + другое название города» Яндекс считает дорвеями → пессимизация («Баден-Баден»/АГС). Поэтому — жёсткие правила.

### 4.1. Когда гео-страницу делать НАДО
Есть реальный спрос (Яндекс Вордстат: частотность «погреб + город» заметная), И мы можем добавить ≥ 30–50% уникального полезного контента. Иначе — статья с гео-уклоном или ничего.

### 4.2. Лимиты
- **Старт: 3–5 городов максимум** (Краснодар, Ростов-на-Дону, Ставрополь, Симферополь, Воронеж — юг РФ логистически выгоден). Не «все города-стотысячники».
- Новые города — по +1–2 в месяц, с полным циклом уникализации. 10–15 гео-страниц — разумный потолок для одного домена без ссылочной массы.
- Каждый город = отдельный URL `/pogreb-{город}/`, одна страница на город (не поддомены — поддомен = отдельный сайт в Вебмастере, отдельное продвижение).

### 4.3. Шаблон уникализации — что ОБЯЗАТЕЛЬНО отличается
Общая структура может повторяться (это нормально), уникальным должно быть:

| Элемент | Правило |
|---|---|
| Title/H1/Description | Только под город, с его спецификой: «Погреб в Ставрополе: доставка 2–3 дня, монтаж за 1 день» |
| Первый экран | Абзац про город: срок доставки из Краснодара, как возим, сколько монтажей сделали в регионе |
| Блок «Особенности региона» | Реальная специфика: глубина промерзания, типичные грунты (глина/суглинок), уровень грунтовых вод, УФ летом, рельеф. Данные брать из СП 131.13330 и открытых источников — не выдумывать |
| Кейсы | Реальные установки в этом городе/регионе (даже 1): фото, размер, срок, особенность монтажа |
| FAQ | 2–3 вопроса привязаны к региону («Доставите в Ставрополь? — Да, 2–3 дня, манипулятор включён») |
| Цена | Региональная вилка доставки, если отличается |

**Тест на дорвей:** если со страницы убрать название города и она останется осмысленной и непохожей на соседнюю гео-страницу — страница готова. Если отличается только город — не публиковать.

### 4.4. Запрещено
- Автогенерация под 50+ городов с подстановкой {город} в один шаблон.
- Перечисления «погреба в Москве, погреба в Туле, погреба в …» списком в тексте (классический сигнал дорвея).
- Поддомены городов (gorod.domen.ru) на одном движке-шаблоне.
- Вхождения ключа «город» чаще ~3–5 раз на страницу.

### 4.5. Регион в Вебмастере
Основной сайт привязан к Краснодару (раздел 0D). Гео-страницы дополнительно регион не «привязывают» — они ранжируются по контенту + коммерческим факторам. NAP на гео-странице тот же (адрес производства Краснодар — это честно и работает). Проверять выдачу по регионам: Вебмастер → «Поиск с учётом региона».

## 5. Скорость

### 5.1. Бюджеты (Core Web Vitals, порог «хорошо»)
| Метрика | Хорошо | Плохо | Что это |
|---|---|---|---|
| LCP | **< 2.5 с** | > 4 с | Отрисовка главного контента |
| INP | **< 200 мс** | > 500 мс | Отклик на действия |
| CLS | **< 0.1** | > 0.25 | Сдвиги вёрстки |

Свои бюджеты (строже CWV, чтобы иметь запас): LCP < 2 с на мобильном; вес первого экрана < 300 КБ; вся страница < 1 МБ; HTML+CSS+JS суммарно < 60 КБ (наш прототип: ~14 КБ HTML со стилями — эталон).

### 5.2. Изображения (обычно 90% проблемы)
- Формат: **WebP q75–82** для всего; hero-картинки можно **AVIF** c WebP-фолбэком (`<picture>`):
```html
<picture>
  <source srcset="img/pogreb.avif" type="image/avif">
  <source srcset="img/pogreb.webp" type="image/webp">
  <img src="img/pogreb.jpg" width="1200" height="800"
       alt="Погреб из полипропилена на участке" fetchpriority="high">
</picture>
```
- Конвертация: `cwebp -q 80 in.jpg -o out.webp`; `ffmpeg -i in.jpg -vf scale=1600:-1 out.avif`. Ресайз под брейкпоинты + `srcset` для больших картинок.
- **LCP-изображение (hero) — никогда `loading="lazy"`!** Наоборот: `fetchpriority="high"` (или `<link rel="preload" as="image">`).
- Всё ниже первого экрана: `loading="lazy" decoding="async"`.
- У каждого `width`/`height` — это ноль CLS. Размер файла фото на карточке: 30–100 КБ.

### 5.3. CSS и шрифты
- Лендинг до ~5 экранов — **весь CSS инлайном в `<head>`** (критический CSS = весь CSS, ~10–15 КБ до gzip). Наш случай — дефолт.
- Многостраничник: общий `style.css` + минификация, один файл, `<link>` в head.
- Шрифты: системный стек = 0 КБ (дефолт). Пользовательский: только woff2, сабсет кириллица+цифры, `font-display:swap` в `@font-face`, preload только для 1 начертания, font metric override, чтобы не было скачка (FOUT → CLS).

### 5.4. JS
- Ванильный JS ≤ 3–5 КБ (как в прототипе: форма → WhatsApp). Никаких jQuery/React/анимационных библиотек.
- Скрипты в конец `body` или `defer`. В `head` без defer — только крошечные критичные вещи.
- Аналитика Метрики — `defer`/асинхронно (сниппет сам асинхронный).

### 5.5. Cloudflare Pages
- Файл `_headers` в корне репозитория:
```
/*
  X-Content-Type-Options: nosniff
  Referrer-Policy: strict-origin-when-cross-origin
  X-Frame-Options: SAMEORIGIN

/img/*
  Cache-Control: public, max-age=31536000, immutable
```
  HTML кэшируется коротко (Pages сам отдаёт `etag`), картинки с версионными именами (`pogreb-v2.webp`) — на год.
- Brotli-сжатие включено на CF по умолчанию — ничего делать не надо.
- Проверять кэш после деплоя: `curl -sI URL` (смотреть `cf-cache-status`).

### 5.6. Как измерять
- PageSpeed Insights (pagespeed.web.dev) — мобильная вкладка, следить за полевыми (CrUX) и лабораторными данными.
- Lighthouse из Chrome DevTools (режим incognito, mobile, Slow 4G).
- Быстрый дым-тест: `curl -o /dev/null -s -w '%{time_total}\n' https://домен/` — ориентир < 0.5 с до первого байла.
- Регламент: проверка после каждого деплоя, полный аудит раз в квартал.
